STM32 HAL printf 重定向原理与实现

在 STM32 裸机工程中，printf 默认走 semihosting 无法输出。通过 fputc/fgetc 重定向 + MicroLIB，将标准输出绑定到 UART。

为什么需要重定向

printf 是 C 标准库函数，底层依赖 fputc 将字符写到某个输出设备。在 ARM 裸机工程中，标准库默认使用 semihosting（半主机模式）：程序通过调试接口把输出请求发给调试器，由调试器打印到 IDE 控制台。

这意味着：

  • 没有连接调试器时，printf 会卡死或无输出
  • 即使连接了调试器，串口监听工具也收不到任何数据
  • 生产环境中 semihosting 完全不可用

要让 printf 输出到 UART，必须把 fputc 重定向到 HAL_UART_Transmit。

工作原理

printf 的调用链如下：

1
2
3
4

printf("text\r\n")
  └─ vfprintf()
       └─ fputc()   ← 这里是可替换的弱符号
            └─ HAL_UART_Transmit()  ← 重定向后走这里

标准库中 fputc 是一个弱符号（weak symbol）。只要在工程中提供一个同名的强符号实现，链接器就会用它替换掉库里的默认版本。

MicroLIB 的作用

Keil 默认链接的是 ARM 标准 C 库（armlib），它内置了完整的 semihosting 支持，fputc 的弱符号替换机制在这个库里不生效。

勾选 Use MicroLIB 后，Keil 改为链接 MicroLIB（一个为嵌入式裁剪的精简 C 库），它：

  • 移除了 semihosting 依赖
  • 将 fputc 暴露为可替换的弱符号
  • 体积更小，适合 Flash 受限的 MCU

路径：Project → Options for Target → Target 选项卡 → 勾选 Use MicroLIB

为什么必须放在 stm32f1xx_hal_msp.c

这是 Keil MDK 链接器的行为问题，不是 C 语言规范问题。

链接器在解析弱符号时，只会在已经参与链接的目标文件中查找强符号。stm32f1xx_hal_msp.c 是 HAL 初始化的核心文件，链接器在处理 HAL 库时必然会加载它，因此放在这里的 fputc 定义一定会被链接器看到。

usart.c 虽然也会被编译，但在某些链接顺序下，链接器可能在解析 fputc 弱符号时还没有处理到 usart.c，导致重定向不生效。

结论：

文件 是否可靠
stm32f1xx_hal_msp.c 可靠，推荐
main.c 通常可靠
usart.c 不可靠，实测无效
其他外设驱动文件 不推荐，链接顺序不确定

实现方法

在 Core/Src/stm32f1xx_hal_msp.c 的 USER CODE BEGIN 1 区域添加：

/* USER CODE BEGIN 1 */
#include <stdio.h>
#include "usart.h"

int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xffff);
    return ch;
}

int fgetc(FILE *f)
{
    uint8_t ch = 0;
    HAL_UART_Receive(&huart1, &ch, 1, 0xffff);
    return ch;
}
/* USER CODE END 1 */

同时在 main.c 中确保包含头文件：

#include <stdio.h>

函数参数说明

fputc 

1

int fputc(int ch, FILE *f)
参数 类型 含义
ch int 要发送的字符，以 int 传入（C 标准规定，实际只用低 8 位）
f FILE * 目标文件流（stdout/stderr 等），裸机中通常忽略，直接发到 UART
返回值 int 成功返回 ch，失败返回 EOF（-1）

(uint8_t *)&ch 取 ch 的地址并转为字节指针，HAL_UART_Transmit 发送 1 字节，超时 0xffff ms（约 65 秒，实际发送极快）。

fgetc 

1

int fgetc(FILE *f)
参数 类型 含义
f FILE * 源文件流，裸机中忽略，直接从 UART 接收
返回值 int 成功返回读取的字符（0~255），失败返回 EOF（-1）

fgetc 是 scanf / getchar 的底层实现，重定向后可以用 scanf 从串口读取输入。

验证

烧录后用串口工具（115200 8N1）监听，每秒应收到：

2
3

text
text
text

收不到数据时按以下顺序排查：

  1. Keil Target 选项中 Use MicroLIB 是否勾选
  2. fputc 是否在 stm32f1xx_hal_msp.c 中
  3. TX/RX 接线是否交叉（STM32 PA9 TX → 模块 RXD，PA10 RX → 模块 TXD）
  4. 波特率是否一致

Ubuntu 根目录爆满危机：一场由 PCIe 日志引发的血案

楔子：黑屏降临

那是一个普通的夜晚，我像往常一样重启了 Ubuntu。

然后——黑屏。

不是那种"等一会儿就好"的黑屏，是那种"我罢工了，你看着办吧"的黑屏。风扇还在转，屏幕却如同一块沉默的黑洞。作为一个从 18.04 一路升级到 24.04 的双系统老用户，我隐约感到事情不简单。

事后回想起来，这其实是系统发出的最后一声呼救，可惜当时我没听懂。

第一章：幕后黑手浮出水面

1.1 第一嫌疑人：根分区

双系统用户都知道，当初装机时给 / 分了 75G，给 /home 分了 135G，心想"够用了够用了"。结果 /home 还剩 35G，根分区却悄无声息地被塞爆了。

为什么会爆？我抱着"让我进去看一眼"的心态，尝试进入 Recovery Mode。

1

df -h

看到 /dev/nvme0n1pX 100% 的那一刻，我知道第一嫌疑人已经锁定了。

1.2 地毯式搜查

进入 root shell 后，我开始了逐层排查：

1
2

# 看看是谁在吃空间
du -xhd1 / | sort -h

重点排查对象：

  • /var — apt 缓存、journal 日志的老巢
  • /usr — Snap 的家
  • /opt — 各种第三方应用的聚居地
  • /tmp — 临时的"遗忘角落"

逐一排查后发现，幕后黑手竟然是——

1
2
3

# 查看日志占用
ls -lh /var/log/syslog
ls -lh /var/log/kern.log

syslog 和 kern.log，加起来 2.9GB。

2.7GB 的系统日志！这是什么概念？正常情况这两个文件加起来也就几十 MB。这就像是家门口的报箱被塞满了同一张传单——有人（或者某个东西）在疯狂地往里面塞东西。

第二章：连环案中案

2.1 日志里的罪证

谁在刷屏？

1

tail -100 /var/log/kern.log

密密麻麻，全是：

1
2
3
4

PCIe AER: BadTLP
PCIe AER: BadTLP
PCIe AER: BadTLP
...

好家伙，**PCIe AER（Advanced Error Reporting）**像个话痨一样，每毫秒都在报告同一个错误：BadTLP（Bad Transaction Layer Packet）。

翻译成人话就是：PCIe 总线上有人在乱发数据包，NVIDIA 显卡或者某个 PCIe 设备间歇性抽风，每抽一次，内核就认真地记一笔。抽了几百万次，内核就记了几百万条。

幕后黑手的幕后黑手，找到了。

2.2 案发现场的更多线索

问题不止一个。除了日志炸弹，这场灾难还暴露出了一串连环案件：

嫌疑人档案：

嫌疑人 罪名 占用空间
PCIe AER 日志 疯狂刷屏 ~2.7 GB
Snap 旧版本缓存 暗度陈仓 数 GB
apt 缓存 长期滞留 数 GB
旧内核 (111) 占着茅坑 ~500 MB
旧内核残留 (55~124) 历史遗留 若干 GB
Docker 镜像 无声膨胀 不定

一个根目录爆满，炸出了六个隐藏问题，这排查体验堪比侦探片。

第三章：内核们的前世今生

3.1 三个内核一台戏

在清理日志、腾出空间、重装 NVIDIA 驱动后，显卡好了——但网卡全没了。

ip link 的输出只有孤零零的 lo、tailscale0 和 docker0。WiFi 和有线网卡，双双人间蒸发。

这时候我发现系统里居然有三个内核：

1
2
3
4

dpkg -l | grep linux-image
# 6.8.0-111-generic  ← 老古董，显卡驱动曾经挂过
# 6.8.0-117-generic  ← 现任劳模，一切正常
# 6.8.0-124-generic  ← 新来的，网卡全灭

故事线是这样的：

1
2
3
4
5
6
7

18.04 → 20.04 → 22.04 → 24.04
         ↓
   内核 111（显卡挂）
         ↓ [装显卡驱动]
   内核 117（一切正常 ✓）
         ↓ [apt upgrade]
   内核 124（网卡消失 ✗）

3.2 124 内核为何成为"网卡杀手"？

破案的关键命令：

1

dpkg -l | grep 6.8.0-124

输出真相大白：

1
2
3
4

ii  linux-image-6.8.0-124-generic           ← 有
ii  linux-modules-6.8.0-124-generic         ← 有
ii  linux-modules-nvidia-580-open-...       ← 有
    linux-modules-extra-6.8.0-124-generic   ← 没有！！！

linux-modules-extra 缺失，这就是网卡消失的全部原因。

Ubuntu 把大量网卡驱动（Intel WiFi、Realtek 有线等）打包在 linux-modules-extra 里面。而 124 内核安装时，根分区已经接近满员，APT 写文件失败，导致这个包没能完整安装。显卡驱动因为是后来单独重装的所以活了，但网卡驱动没人管，就这么被遗忘了。

这就像搬家时搬了床和冰箱，却把路由器和网线落在了旧房子。

第四章：拯救大作战

4.1 紧急避险：回到 117 

1
2
3

# 进 GRUB → Advanced options → 选 6.8.0-117 启动
# 果然，网卡和显卡都在
ip link   # wlp..., enp... 全回来了 ✓

4.2 清扫战场：删除 111 内核 

1
2
3
4
5
6
7
8
9

sudo apt purge \
  linux-image-6.8.0-111-generic \
  linux-headers-6.8.0-111-generic \
  linux-modules-6.8.0-111-generic \
  linux-modules-extra-6.8.0-111-generic

sudo apt autoremove --purge
sudo apt clean
sudo update-grub

4.3 大扫除：清理残留

那些标记为 rc（已卸载但配置残留）的包，从 18.04 时代一路攒到 24.04：

1
2

# 一键清除所有 rc 残留
sudo dpkg -l | awk '/^rc/{print $2}' | xargs sudo dpkg --purge

这包括了：

  • 旧版本 linux-image（55, 56, 57… 一路攒过来的）
  • 旧版本 NVIDIA 驱动（550 系列残留）
  • 各种历史遗留配置

4.4 修复 124：给新内核补票

在 117 内核下（有网络），把 124 缺失的包装上：

1

sudo apt install linux-modules-extra-6.8.0-124-generic

然后重启进 124 验证——网卡回来了！

4.5 永绝后患：封印 PCIe AER 

1
2
3
4
5

sudo vim /etc/default/grub
# 在 GRUB_CMDLINE_LINUX_DEFAULT 里加上：
# pci=noaer

sudo update-grub

这一个参数，让你的系统日志从此告别话痨模式。即使 NVIDIA 以后还想抽风，也不会再炸满你的根分区。

NVIDIA PCIe 间歇性错误
        ↓
PCIe AER 疯狂记录 BadTLP
        ↓
kern.log & syslog 膨胀到 2.7GB
        ↓
根分区 100% 满
        ↓
系统无法启动（黑屏）
        ↓
Recovery Mode 清理日志 + 重装 NVIDIA 驱动
        ↓
内核意外升级到 124
        ↓
根分区满致 linux-modules-extra 安装失败
        ↓
网卡驱动缺失（显卡因为单独重装所以幸存）
        ↓
切回 117 内核 → 补装 extra → 达成全线恢复

核心教训

  1. 别让根分区太小 — 50G 对于 ROS2 + Docker + CUDA 开发来说太紧张了
  2. pci=noaer 是你的朋友 — 遇到 NVIDIA PCIe 报错，先封印 AER
  3. 新内核出问题？立刻切回旧内核 — GRUB 就是你最好的后悔药
  4. 定期 apt autoremove + apt clean — 特别是从低版本一路升级上来的系统
  5. 别在根分区满的时候升级内核 — 先清空间，再升级，否则模块安装不完整就是今天的剧本

最后

这场排查耗时两天，从黑屏恐慌到精准定位，从内核追凶到日志封印。写下来，既是给自己留个备份，也希望下一个遇到类似问题的倒霉蛋，能少走点弯路。

毕竟，Linux 用户的日常就是：今天写的 Bug 记录，就是明天别人的救命稻草。

ROS2 串口通信握手失败：DTR/RTS 导致 STM32 进入 bootloader

通过USB串口与STM32通信时版本查询握手失败，原因是Linux打开串口时DTR/RTS同时拉高，STM32进入bootloader 而非运行应用程序。

2026-05-16
2 minute read
loading... 次

现象

ROS2 arm_base 节点打开 /dev/ttyUSB0 后发送版本查询帧 55 55 02 01，下位机 STM32 无任何回复。

1
2
3
4

[arm_base-1] 串口已打开: /dev/ttyUSB0 @ 9600
[arm_base-1] 已发送版本查询: 55 55 02 01
[arm_base-1] 版本查询回复长度错误: 期望 6, 实际 0
[arm_base-1] 串口通信握手失败，坐标指令将被丢弃。

另外：关掉终端后舵机会轻微响一声——说明 STM32 硬件正常，但只在串口关闭后才启动。

调试过程

1. 检查波特率和协议

比对下位机协议和上位机代码：

  • 波特率：9600，8N1，一致
  • 帧格式：[0x55][0x55][data_len][cmd][payload...]，一致
  • 版本查询帧：55 55 02 01，正确

2. 检查上位机代码

检查 arm_base.cpp 和 serial 库代码：

  • 串口配置正确（9600, 8-bit, no parity, 1 stop bit）
  • 数据发送逻辑正确
  • 超时设置 100ms，足够 STM32 回复

怀疑是串口打开时 DTR 拉高导致 STM32 复位，加 2 秒延时，无效。

3. 检查下位机代码

对照协议文档审查 STM32 固件逻辑：

  • unpack() 状态机正常，data_len=2 时读 0 字节 payload 合法
  • CMD_VERSION_QUERY 分支会回复 6 字节
  • 未发现固件侧问题

4. 官方上位机软件测试

用厂商提供 Windows 上位机软件测试，可以正常控制机械臂。排除硬件故障和固件 bug。

5. 串口调试助手测试

Windows 端用串口调试助手直接发 55 55 02 01，STM32 正常回复 55 55 04 01 02 01。

说明：

  • STM32 硬件、固件、接线全部正常
  • 问题一定在 Linux 端串口通信层面

6. echo 直接写串口（无效尝试） 

1

echo "05 05 02 01" > /dev/ttyUSB0

无反应。后来才发现两个问题：

  1. echo 发送的是 ASCII 文本 "05 05 02 01\n"，不是二进制 hex \x55\x55\x02\x01
  2. 当时 STM32 拔插过，/dev/ttyUSB0 被 echo 重定向创建成了普通文件而非字符设备

但之前 ROS2 程序发送的是真正的二进制数据，所以问题不在这里。

7. Python 脚本逐步诊断

用 Python + pyserial 写调试脚本，打印 modem 线状态：

1
2
3

ser = serial.Serial('/dev/ttyUSB0', 9600)
# 打印 DTR/RTS 状态
flags = fcntl.ioctl(ser.fd, termios.TIOCMGET, ...)

结果：

  • open() 后：DTR=High, RTS=High
  • ser.dtr = False 后：DTR=Low, RTS=High ← DTR拉低了但STM32仍未启动

加上 “关终端舵机会响” 的现象，怀疑RTS连接到了BOOT0。

8. 验证：RTS先拉低再拉低DTR 

1
2
3
4
5
6
7

ser.rts = False    # 先拉低 RTS → BOOT0=0
time.sleep(0.1)
ser.dtr = False    # 再拉低 DTR → 释放复位
time.sleep(2)
ser.write(b'\x55\x55\x02\x01')
rx = ser.read(6)
# 收到：55 55 04 01 02 01  ← 握手成功！

根因

Linux 打开串口时 DTR 和 RTS 同时被拉高。

STM32 板子实际硬件连接：

信号 连接 高电平效果
DTR RESET STM32 处于复位状态
RTS BOOT0 复位后进入 ROM bootloader

如果只拉低 DTR（释放复位）而 RTS 仍为高，STM32 复位后检测到 BOOT0=1，进入 ROM bootloader 模式，应用程序不运行，自然不会回复版本查询。

当程序退出 / 终端关闭时，RTS 被释放变低，STM32 再次复位 → BOOT0=0 → 正常启动 → 舵机响一声。

解决

打开串口后，必须先拉低 RTS，再拉低 DTR：

1
2
3
4
5

arm_serial_.open();
arm_serial_.setRTS(false);                          // BOOT0=0，确保正常启动
std::this_thread::sleep_for(std::chrono::milliseconds(100));
arm_serial_.setDTR(false);                          // 释放复位
std::this_thread::sleep_for(std::chrono::seconds(2)); // 等待启动

知识点

  • Linux open() TTY 设备时，内核会拉高 DTR 和 RTS
  • STM32 BOOT0 引脚决定启动模式：低电平=闪存启动(正常)，高电平=系统存储器(bootloader)
  • 用 TIOCMGET ioctl 可以读取 modem 线实际状态，比盲猜高效
  • echo "hex" > /dev/ttyUSB0 写入的是 ASCII 文本，不是二进制——要用 echo -ne "\xHH\xHH"
  • pyserial 的 ser.dtr / ser.rts 属性可以控制 modem 线
